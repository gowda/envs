# S3

This guide explains configuration, snapshots and publishing for people working with env files in Amazon S3. Start with the [README configuration table](../README.md#configuration) for the four settings.

## Configuration

Settings and secrets come from environment variables. Restart the app after you change a setting. Configure credentials through the standard AWS credential chain.

See [Configuration in the README](../README.md#configuration) for the S3 permissions and the command to generate an encryption key.

Keep `ENVS_ENCRYPTION_KEY` stable and store it securely. Existing snapshots require the same key. The app uses a fixed salt for key derivation and does not use Rails credentials. The test environment uses an invented encryption key.

## Selection and refresh

Open `/s3` to view local snapshots of S3 files. Select **Refresh from S3** to fetch current files and remove snapshots of deleted files. Select a file card to view its variables.

The app selects object base names that are `.env`, start with `.env.`, or end with `.env`. `ENVS_S3_PREFIX` limits the listing; its default is an empty prefix.

Files over 1 MB have a **Too large** error label. The app does not download them. Invalid files have an **Invalid env file** error label, and their content stays encrypted in the local snapshot. Both sources follow the [env file format](env-file-format.md).

Refresh keeps a choice while the count of lines with that name stays the same. It deletes a choice if the count changes or the file disappears. Refresh removes a value edit if its name is gone or the line that stays already contains that value.

## Editing

Only valid S3 snapshots can be edited. Uploaded files cannot be edited.

Select **Edit** on a variable, enter a value and select **Save** to keep a local change for that name. A value edit changes the line that stays, or the last line when there is no choice. It changes no other text.

Values stay literal. An empty value is valid. A value must use UTF-8 and must not contain CR or LF.

A **Modified** label identifies each changed row and file card. A **Leading or trailing whitespace** label identifies values with spaces or tabs at either end. A **Repeated names** label identifies cards whose files repeat a name; without a choice, earlier rows have an **Overridden** label.

For a repeated name, select **Resolve** in the warning. Choose a line and select **Keep selected line**. The default is your pending choice, or the last line. **Cancel** returns without saving. **Change** reopens a choice, and **Keep every line** deletes it. If the count changed since you opened the form, refresh the file before choosing again.

The warning identifies the line that stays and the lines a publish removes. Those rows have a **Removed** label and no **Edit** link. The line that stays has the **Edit** link. A choice also marks the file card **Modified**. If a value edit equals the value of the line that stays after a choice changes, the app removes that edit.

Select **Discard changes** to remove all value edits and choices for a file.

## Review and publish

Select **Review & publish** to review the difference, then select **Publish** to write the file to S3.

A publish removes the unselected lines with their line endings, applies value edits and adds no lines. It preserves all other text, including indentation, line endings and a byte order mark at the start. A successful publish updates the snapshot and clears value edits and choices together.

The review shows removed lines in red, changed lines in red and green, and three unchanged lines around changes. Old and new line numbers account for removals.

A publish preserves the content type, metadata and encryption settings from S3. It does not keep object tags, the ACL (access control list), cache settings or storage class.

An ETag is a tag that S3 changes when an object's content changes. The publish uses the stored ETag as a condition to avoid overwriting a changed object. If the S3 ETag changed, publishing stops without overwriting the object. Refresh the snapshots and review the local changes again before publishing.
