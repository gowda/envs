# S3

This guide explains configuration, snapshots and publishing for people working with env files in Amazon S3. Start with the [README configuration table](../README.md#configuration) for the four settings.

## Configuration

Settings and secrets come from environment variables. Restart the app after you change a setting. Configure credentials through the standard AWS credential chain.

See [Configuration in the README](../README.md#configuration) for the S3 permissions and the command to generate an encryption key.

Keep `ENVS_ENCRYPTION_KEY` stable and store it securely. Reading or writing a secret value requires this key. Plain and undecided values need no key. The app uses a fixed salt for key derivation and does not use Rails credentials. The test environment uses an invented encryption key.

## Selection and refresh

Open `/s3` to view local snapshots of S3 files. Select **Refresh from S3** to fetch current files. Select a file card to view its variables.

The app selects object base names that are `.env`, start with `.env.`, or end with `.env`. `ENVS_S3_PREFIX` limits the listing; its default is an empty prefix.

Files over 1 MB have a **Too large** error label. The app does not download them. Invalid files have an **Invalid env file** error label. Both errors keep the previous variable rows and types. Both sources follow the [env file format](env-file-format.md).

SQLite stores a file reference and state in `env_files`, and one row per assignment in `env_file_variables`. Each assignment keeps its position, line number, name, value and type. The app stores no object text, comments or lines without `=`. It keeps only the line numbers for that warning.

Refresh replaces the variable rows from valid objects. It keeps pending changes, including changes for missing names, invalid files and files over 1 MB. It removes a value edit when its line already contains the requested value. It removes a deleted file's snapshot only when that snapshot has no pending changes.

## Editing

Only valid S3 snapshots can be edited. Uploaded files cannot be edited.

Select **Edit** on a variable, enter a value and select **Save** to keep a local change for that name. A value edit changes the line that stays, or the last line when there is no choice. It changes no other text.

Values stay literal. An empty value is valid for a plain or undecided name. A value must use UTF-8 and must not contain CR or LF.

A **Modified** label identifies each changed row and file card. A **Leading or trailing whitespace** label identifies values with spaces or tabs at either end. A **Repeated names** label identifies cards whose files repeat a name; without a choice, earlier rows have an **Overridden** label.

For a repeated name, select **Resolve** in the warning. Choose a line and select **Keep selected line**. The default is your pending choice, or the last line. **Cancel** returns without saving. **Change** reopens a choice, and **Keep every line** deletes it. If the count changed since you opened the form, refresh the file before choosing again.

The warning identifies the line that stays and the lines a publish removes. Those rows have a **Removed** label and no **Edit** link. The line that stays has the **Edit** link. A choice also marks the file card **Modified**. If a value edit equals the value of the line that stays after a choice changes, the app removes that edit.

Select **Discard changes** to remove all value edits and choices for a file.

## Secret and plain

Each variable has a type: secret or plain. A name with no saved type is plain and undecided.

Above the variable list, **Suggestions** shows undecided names that look like secrets. The suggestion uses the name, without reading its value. Select **Mark as secret** to save secret, or **Dismiss** to save plain and remove the suggestion. The app sets a type only when you request it.

The edit page shows the type and a **Mark as secret** or **Mark as plain** button. Each row of a secret name has a **Secret** label. Repeated names share one type.

Secret values appear as `••••••••`, a fixed mask for every value. The response contains no hidden copy of a masked value, pending value or base. Plain and undecided values stay visible. **Mark as plain** makes a value visible immediately; **Mark as secret** masks it immediately.

Select **Show** to see one name's values on the file, edit, repeated-name choice or review page. The button posts the name and returns the same page without a redirect. Other secrets stay masked. **Hide**, or a reload of the normal page, restores the mask. The app stores no reveal state and sends `Cache-Control: no-store` on every S3 response.

A secret's edit field stays empty, including after **Show**. **Show** displays the current and pending values as text and reveals both values in a conflict box. Type a value before saving. An empty field saves nothing and shows **Type a value.** A refused save also empties the field, so you must type the value again.

In the review, secret lines keep their text through the first `=` and mask everything after it. This includes old, new and nearby unchanged lines. One **Show** button reveals every review line of that name. Review **Show** fetches and checks the S3 object again, like the normal review.

A type takes effect immediately and is not a pending change. It does not mark a file **Modified** or appear in the review. Changing a type immediately stores every row value, pending value and base of that name again under the new type.

Discarding changes and publishing keep types. Refresh keeps a type while its name stays, including new lines of that name. A name that leaves loses its type; its return is undecided.

## Conflicts

Secret values use Active Record encryption in the database. Plain and undecided values stay as written. Pending values and bases follow their name's type, including the ordered bases for a repeated name.

Each pending change keeps a base: the value or ordered values you saw when you saved. A refresh compares the new rows with those bases. Changes to names without pending changes need no action from you.

The **Conflicts** box identifies each conflict. A **Conflict** label marks affected rows and file cards. **Review & publish** stays disabled until you resolve every conflict. **Discard changes** removes all pending changes.

- If a value changed in S3 after your edit, select **Resolve**. The edit page shows the original and current S3 values, masked for a secret until you select **Show**. Select **Save** to accept your field value with the current S3 value as its new base. Select **Use the S3 value** to delete only that edit. This button also works without a conflict.
- If a name disappeared from S3, select **Discard the change** beside its conflict.
- If the count or values of a repeated name changed, select **Resolve** and choose again. The default is the last line. **Keep selected line** saves a new base, and **Keep every line** deletes the choice.
- If a name is no longer repeated or has disappeared, select **Discard the choice**.

While a choice is in conflict, the last line takes effect and no row has a **Removed** label. Changing or deleting a choice moves a value edit to its new line. If that edit was already in conflict, its original base stays.

The edit form also checks the snapshot's ETag when you save. If another refresh changed it, nothing is saved. Check the current values and save again.

If the file disappeared from S3, its card shows **Deleted in S3**. Its snapshot and pending changes stay available, with editing, resolving and publishing unavailable. Secrets stay masked, and **Show** still works on the file page. **Discard changes** deletes the snapshot and returns you to `/s3`. If a later refresh finds the file again, the app compares it with your bases and shows any conflicts.

Invalid files and files over 1 MB keep all pending changes and show their error without computing conflicts. A later valid snapshot makes those comparisons again.

## Review and publish

Select **Review & publish** to review the difference, then select **Publish** to write the file to S3.

A publish removes the unselected lines with their line endings, applies value edits and adds no lines. It preserves all other text, including indentation, line endings and a byte order mark at the start. A successful publish replaces the rows from the published text, keeps the types and clears value edits and choices together.

Review and publish fetch the object from S3. Its ETag must equal the stored ETag, and its parsed entries must equal the rows. Otherwise, the app refreshes the rows and returns to the file page with **The file changed in S3. Check your changes.** Each conflict appears there. If S3 cannot be reached, review shows the refresh error.

The review shows removed lines in red, changed lines in red and green, and three unchanged lines around changes. Old and new line numbers account for removals.

A publish preserves the content type, metadata and encryption settings from S3. It does not keep object tags, the ACL (access control list), cache settings or storage class.

An ETag is a tag that S3 changes when an object's content changes. A publish uses the stored ETag as a condition to avoid overwriting a changed object. If the condition fails, the app fetches that object and shows any conflicts on its file page. Check the changes again before publishing. If S3 reports that the object is gone, the app records its deletion and keeps your changes. The app does not create an object.
